# **Спецификация программных требований** 

## **1.Введение**

### **1.1. Назначение**

Данный документ описывает функциональные и нефункциональные требования к приложению Будильник.

Назначение этой спецификации \- предоставить полное, однозначное и понятное описание программных требований, которое может быть использовано разработчиками, тестировщиками и другими заинтересованными лицами.

### **1.2. Область применения**

Будильник \- приложение на персональный компьютер или мобильный телефон, позволяющий управлять “будильниками” \- создавать, удалять, изменять, отключать и включать.

Приложение должно уведомлять пользователя в заданное заранее время с помощью звука, текстового уведомления и вибрации если они были установлены.

Помимо этого, приложение должно также предлагать возможность отключить или перевести будильник на на 5 минут.

Предполагаемая аудитория \- пользователи мобильных телефонов на базе Android и iOS.

### **1.3. Определения, акронимы и сокращения**

**Будильник** \- событие, которое выводит на экран пользователя уведомление в заданный промежуток времени и сообщает пользователю об этом с помощью звуковых и вибро-сигналов, если таковые были заданы.

**Отложить \-** опция, позволяющая перенести событие Будильник на заданный промежуток времени.

**Отключить \-** опция, позволяющая отключить воспроизведение события Будильник до следующего дня либо навсегда.

**UI \-** User Interface, интерфейс пользователя.

**ФТ \-** функциональное требование.

**НФТ \-** нефункциональное требование.

**Система** \- операционная система телефона, внешняя система в которой будильник должен быть зарегистрирован как событие.

## **2.Обзор системы**

Приложение Будильник это автономное приложение для телефонов. Приложение должно использовать системные функции установки и управления будильниками для уведомления пользователя в заданное при создании время.

В приложении должна быть возможность создавать, изменять, удалять, просматривать, переносить, отключать будильники.

Приложение должно взаимодействовать со следующими внешними компонентами:

* ОС телефона  
* Аудиосистема устройства  
* Вибросистема устройства  
* Системные часы

## **3.Детальные требования**

### **3.1. Функциональность**

#### **3.1.1. Создать будильник**

**ID:** ФТ-01 

**Краткое описание:** опция создания нового будильника.

**Акторы:** Пользователь.

**Предусловия:** Пользователь открыл приложение на телефоне.

**Постусловия:** Новый будильник появился в списке существующих.

**Основной поток:** 

1. Пользователь выбирает опцию создания нового будильника  
2. Пользователь вводит необходимые данные:  
   1. Время  
   2. Повтор (однократно, по будням, ежедневно).  
   3. Мелодия звонка (выбирается из существующих в памяти телефона пользователя)  
   4. Должен ли телефон вибрировать при срабатывании.  
   5. Описание  
3. Пользователь выбирает опцию Сохранить.  
4. Приложение сохраняет полученные данные и создает уведомление, которое должно быть показано в заданное время.  
5. Приложение выводит созданный будильник в списке существующих будильников.

**Альтернативные и исключительные сценарии:**

**Пункт 2.1.** Если не введены обязательные данные, приложение должно подсветить поле красным цветом. Кнопка сохранения должна быть заблокирована.  
**Пункт 2.2.** Если пользователь ввел описание будильника длиной больше 100 символов, то приложение должно подсветить это поле красным цветом и вывести сообщение “Описание будильника должно быть длиной не более 100 символов, включая пробелы и спец. символы.”  
**Пункт 3.1.** Пользователь выбрал опцию “Закрыть”. Приложение должно стереть введенные данные и закрыть экран создания будильника.

**Критерии приемки:**

* Созданный будильник сохраняется в системе и выводится на экран со списком существующих будильников.  
* Незаполненные обязательные поля подсвечиваются.  
* Поле описания будильника подсвечивается при превышении лимита длины поля.  
* Созданный будильник должен быть автоматически установлен как активный, т.е. должен сработать в заданное время.

#### **3.1.2. Изменить будильник**

**ID:** ФТ-02

**Краткое описание:** процесс изменения данных будильника.

**Акторы:** Пользователь.

**Предусловия:** Пользователь открыл приложение на телефоне, есть активные будильники.

**Постусловия:** Данные будильника изменены, новые данные выведены в списке активных.

**Основной поток:** 

1. Пользователь выбирает будильник из списка.  
2. Приложение выводит данные:  
   1. Время  
   2. Повтор (однократно, по будням, ежедневно).  
   3. Мелодия звонка (выбирается из существующих в памяти телефона пользователя).  
   4. Должен ли телефон вибрировать при срабатывании.  
   5. Описание.  
   6. Статус \- Активен или Отключен.  
      1. Если повтор указан как Ежедневно или По будням и будильник уже сработал или был отключен, то рядом со статусом должна быть выведена дата следующего срабатывания.  
   7. Кнопки Изменить и Удалить.  
   8. Кнопка Включить выводится:  
* Если будильник находится в статусе Отключен без указанной даты следующего срабатывания.  
* Повтор указан как Ежедневно и будильник был отключен до времени срабатывания.  
  9. Кнопка Отключить выводится, если статус будильника \- Активен.  
3. Пользователь выбирает опцию Изменить.  
4. Приложение показывает модальное окно с полями для изменения (окно аналогично окну создания) и кнопками Сохранить и Закрыть.  
5. Пользователь изменяет необходимые данные и выбирает опцию Сохранить.  
6. Приложение сохраняет полученные данные и изменяет заданное уведомление.  
7. Приложение выводит обновленную информацию о будильнике в списке существующих.

**Альтернативные и исключительные сценарии:**

**Пункт 4.1.** Пользователь выбрал опцию “Закрыть”. Приложение должно закрыть окно изменения, данные будильника не должны быть изменены.  
**Пункт 5.1.** Если не введены обязательные данные, приложение должно подсветить поле красным цветом. Кнопка сохранения должна быть заблокирована.  
**Пункт 5.2.** Если пользователь ввел описание будильника длиной больше 100 символов, то приложение должно подсветить это поле красным цветом и вывести сообщение “Описание будильника должно быть длиной не более 100 символов, включая пробелы и спец. символы.”  
**Пункт 5.4.** В случае системной ошибки приложение должно вывести уведомление “Возникла непредвиденная ошибка. Приложение будет закрыто, попробуйте снова позднее.”

**Критерии приемки:**

* Данные будильника изменяются в системе и выводятся на экран со списком существующих будильников.  
* Незаполненные обязательные поля подсвечиваются.  
* Поле описания будильника подсвечивается при превышении лимита длины поля.  
* Измененный будильник должен быть автоматически установлен как активный, т.е. должен сработать в заданное время.  
* Измененный будильник должен сработать в новое время (если оно было изменено).

**Основной поток:**

   6. Статус \- Активен или Отключен.  
      1. Если повтор указан как Ежедневно или По будням и будильник уже сработал или был отключен, то рядом со статусом должна быть выведена дата следующего срабатывания.

**Критерии приемки:**

* Удаленный будильник не воспроизведется в заданное время, т.е. был полностью удален.

**Критерии приемки:**

* Приложение корректно вывело информацию по выбранному будильнику.

#### **3.1.5.  Срабатывание будильника**

**ID:** ФТ-05

**Краткое описание:** Процесс срабатывания будильника 

**Акторы: \-** 

**Предусловия:** Пользователь создал будильник, системное время телефона равно указанному в настройках будильника, будильник имеет статус Активен.

**Основной поток:** 

1. Будильник срабатывает.  
2. Приложение запускает проигрыш заданного в настройках будильника звука.  
3. Приложение активирует настройки вибрации телефона, если те были включены в настройках будильника.  
4. Приложение выводит уведомление о срабатывании будильника с текстом, заданным при создании будильника, а также кнопки Отложить на 5 минут и Отключить.

**Альтернативные и исключительные сценарии:**

Будильник не должен срабатывать в следующих ситуациях:

1. Телефон отключен или разряжен \- при последующем включении приложение должно сравнить системное время и время будильника и пометить его как активный или сработавший.  
2. Пользователь вручную перевёл часы или устройство синхронизировало время с сетью.  
3. Изменился часовой пояс.  
4. ОС ограничила работу приложения в фоне.  
5. Будильник был удален или отключен.  
6. Системная ошибка.

Если пользователь не отключил и не перенес будильник, то звук будильника должен воспроизводиться в течении 1 минуты, после чего будильник должен быть автоматически перенесен.

**Критерии приемки:**

* Будильник сработал в назначенное время.

#### **3.1.6.  Отключить сработавший будильник**

**ID:** ФТ-06

**Краткое описание:** опция отключения сработавшего будильника

**Акторы:** Пользователь

**Предусловия:** Будильник сработал, уведомление выводится на экране телефона.

**Постусловия:** Будильник отключен, приложение создало внутри ОС телефона следующее системное событие этого будильника с выводом уведомления.

**Основной поток:** 

1. Пользователь видит уведомление сработавшего будильника и опции Отключить и Отложить на 5 минут.  
2. Пользователь выбирает опцию Отключить.  
3. Приложение отключает звук, убирает уведомление с экрана телефона и переводит будильник в статус Отключен.  
   1. В зависимости от установленного кол-ва повторов, статус Отключен должен показывать до какого времени он отключен (до даты завтрашнего дня либо до даты, которая соответствует дню недели Понедельник).  
4. В зависимости от установленного кол-ва повторов, приложение должно задать следующее системное событие на вывод уведомления этого же будильника в заданное время с заданными параметрами звука, вибрации и описанием. 

**Альтернативные и исключительные сценарии:**

**Пункт 2.1.** Если пользователь не отключил и не перенес будильник, то звук будильника должен воспроизводиться в течении 1 минуты, после чего будильник должен быть автоматически перенесен на 5 минут вперед.

**Критерии приемки:**

* Будильник отключен после нажатия кнопки.  
* Будильник перенесен по прошествии 1 минуты.

#### **3.1.7.  Перенести сработавший будильник.**

**ID:** ФТ-07

**Краткое описание:** Опция переноса сработавшего будильника на 5 минут вперед.

**Акторы:** Пользователь

**Предусловия:** Будильник сработал, уведомление выводится на экране телефона.

**Постусловия:** Будильник перенесен, приложение создало внутри ОС телефона следующее системное событие этого будильника с выводом уведомления через 5 минут от текущего времени.

**Основной поток:** 

1. Пользователь видит уведомление сработавшего будильника и опции Отключить и Отложить на 5 минут.  
2. Пользователь выбирает опцию Отложить на 5 минут.  
3. Приложение отключает звук, убирает уведомление с экрана телефона и задает следующее системное событие на вывод уведомления этого же будильника через 5 минут от текущего времени с заданными при создании звуком, вибрацией и описанием будильника. 

**Альтернативные и исключительные сценарии:**

**Пункт 2.1.** Если пользователь не перенес будильник, то звук будильника должен воспроизводиться в течении 1 минуты, после чего будильник должен быть автоматически перенесен.

**Критерии приемки:**

* Будильник перенесен на 5 минут вперед по требованию пользователя.  
* Будильник перенесен на 5 минут вперед по прошествии 1 минуты и пользователь не отключил и не перенес его вручную.

   3. Мелодия звонка (выбирается из существующих в памяти телефона пользователя)  
   4. Должен ли телефон вибрировать при срабатывании.  
   5. Описание  
   6. Статус \- Отключен.  
      1. Если Повтор указан как Ежедневно или По будням и будильник уже сработал или был отключен, то рядом со статусом должна быть выведена дата следующего срабатывания.  
   7. Кнопки Изменить и Удалить.  
   8. Кнопка Включить.  
4. Пользователь выбирает опцию Включить.  
5. Приложение переводит будильник в статус Активен и создает в системе событие на вывод уведомления о срабатывании в заданное время.

**Альтернативные и исключительные сценарии:**

**Критерии приемки:**

* Будильник включен и срабатывает в назначенное время.

#### **3.1.9. Отключить будильник**

**ID:** ФТ-09

**Краткое описание:** опция отключения будильника. 

**Акторы:** Пользователь.

**Предусловия:** Будильник находится в статусе Активен.

**Постусловия:** Будильник находится в статусе Отключен.

   1. Время.  
   2. Повтор (однократно, по будням, ежедневно).  
   3. Статус Активен.  
2. Пользователь выбирает из списка активный будильник.  
3. Приложение выводит подробную информацию по будильнику и доп. опции:  
   1. Время  
   2. Повтор (однократно, по будням, ежедневно).  
   3. Мелодия звонка (выбирается из существующих в памяти телефона пользователя)  
   4. Должен ли телефон вибрировать при срабатывании.  
   5. Описание  
   6. Статус \- Активен.  
   7. Кнопки Изменить и Удалить.  
   8. Кнопка Отключить.  
4. Пользователь выбирает опцию Отключить.  
5. Приложение переводит будильник в статус Отключен и удаляет из системы все события на вывод уведомления о срабатывании этого будильника.  
6. Пользователь видит обновленную информацию по будильнику.

**Альтернативные и исключительные сценарии:**

**Пункт 4.1.** В случае системной ошибки приложение должно вывести уведомление “Возникла непредвиденная ошибка. Приложение будет закрыто, попробуйте снова позднее.”. Будильник остается в статусе Включен.

**Критерии приемки:**

* Будильник отключен, события по выводу уведомления о срабатывании будильника удалены.
